# Физмат-тренажёр: поступление в 8 класс

Статический тренажёр для учеников 6–7 классов, готовящихся к вступительным испытаниям в физико-математические лицеи. Работает на **GitHub Pages** без сервера: Vanilla JS, адаптивный интерфейс, автоматическая проверка и отправка результата ДЗ в Telegram.

> Банк содержит **105 задач**: по 5 типовых задач на каждую из 21 тем. Есть числовой ввод, выбор ответа и геометрическое сопоставление drag-and-drop (с удобным касанием на телефоне).

## Локальный запуск

Откройте папку через любой статический сервер, например:

```bash
python3 -m http.server 8000
```

Затем перейдите на `http://localhost:8000`. Для локальной отправки в Telegram скопируйте `js/config.example.js` в `js/config.js`, задайте значения и **не добавляйте этот файл в Git**.

## Telegram: настройка и безопасность

1. Создайте бота в [@BotFather](https://t.me/BotFather) и получите Bot Token.
2. Откройте диалог с ботом, нажмите **Start**, затем узнайте свой `chat_id` через [@userinfobot](https://t.me/userinfobot) (для группы добавьте бота и используйте `getUpdates`).
3. В репозитории откройте **Settings → Secrets and variables → Actions → New repository secret** и создайте:
   - `BOT_TOKEN` — токен от BotFather;
   - `TG_CHAT_ID` — id чата получателя.
4. Workflow `.github/workflows/deploy.yml` при каждом push создаёт `js/config.js` только внутри deployment-артефакта.

### Важное ограничение статического сайта

GitHub Secrets защищают токен **от попадания в публичный репозиторий**, но не способны сделать секретным токен, который браузер должен отправить в `api.telegram.org`: его можно увидеть в загруженном JavaScript на опубликованной странице. Поэтому для реального постоянного проекта рекомендуется бесплатный **Cloudflare Worker**: хранить `BOT_TOKEN` как Worker Secret и вызывать из браузера только Worker URL. Прямой клиентский режим здесь оставлен по требованию проекта.

Если токен уже передавался в чате, коммитах, логах или открытом JavaScript, считайте его скомпрометированным: в @BotFather выполните `/revoke`, возьмите новый токен и обновите `BOT_TOKEN` в GitHub Secrets. Аналогично удалите/перевыпустите GitHub PAT в **Settings → Developer settings → Personal access tokens**.

## GitHub Pages

Workflow запускается на `push` в `main` и публикует содержимое корня. В **Settings → Pages** должен быть выбран источник **GitHub Actions**. Нужные permissions workflow уже описаны в `deploy.yml`.

Для автоматического создания Pages и Actions Secrets через GitHub API PAT должен иметь права на репозиторий и Actions secrets (`repo` для classic PAT либо fine-grained access: Administration read/write, Actions secrets read/write, Contents read/write, Pages read/write). Создание public repo также требует разрешения на создание репозиториев.

## Как расширить банк задач

- Уроки находятся в `data/lessons.json`.
- Все задания — в `data/tasks.json`.
- Для каждого урока добавляйте 5–10 объектов с тем же `lessonId`.
- `type` может быть `input`, `choice` или `drag`.
  - `input`: `answer` — число, дробь или строка; числа проверяются с допуском ±0.01, дроби и десятичные записи эквивалентны.
  - `choice`: добавьте `choices: [{key, text}]`, а `answer` задайте ключом.
  - `drag`: задайте `items`, `targets` и объект `answer`, например `{"A":"BC"}`.

После изменения JSON выполните `git add`, `git commit` и `git push` — GitHub Actions задеплоит новую версию.
